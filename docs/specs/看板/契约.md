# 看板契约 v1（2026-09-18）

页面只认这份契约，不认任何业务字段（Q16-A）。数据来源换了（工作台台账 → 公司接口），页面一行不改。
公司接口只要照这个形状吐，或者在 `adapters/` 里被转成这个形状，都行（Q22-A）。

**三条铁律**（都是工作台踩出来的）：
1. **顺序走数组**：块、指标、列、行、点全是数组，顺序即显示顺序。不许靠 dict 键序（`§2.18.5`）。
2. **算不出来给 `null` + `reason`，不给 0**（`§2.12`）：缺一天台账是「缺」，画成 0 是深坑。
3. **截断必须自报**（`§2.16.5`）：表被砍了要写 `truncated: {shown, total}`。

## 接口

所有 `/api/dashboard/*` 要 `Authorization: Bearer <口令>`；口令是按人配的（`dashboard.viewers`）。
对不上或已停用 → `401 {"ok":false,"code":401,"msg":"口令不对或已停用"}`。
唯一例外 `GET /api/dashboard/health`（不要口令，只回 `{"ok":true,"service":"dashboard"}`）。

| 接口 | 回什么 |
|---|---|
| `GET /api/dashboard/sources` | `{"ok":true,"sources":[{"key":"workbench","label":"工作台台账","configured":true,"reason":""},{"key":"company","label":"公司接口","configured":false,"reason":"未配 dashboard.company_api.base_url"}]}` |
| `GET /api/dashboard/dates?source=workbench` | `{"ok":true,"source":"workbench","dates":["2026-09-17","2026-09-16",…],"latest":"2026-09-17"}`（倒序；一天都没有也是 200，`dates:[]`，`latest:null`，带 `reason`） |
| `GET /api/dashboard/daily?source=workbench&date=2026-09-17` | 下面的「日报」。不给 `date` = 最新那天。没那天也是 200：`ok:false` + `reason`，`blocks` 里每块各自 `ok:false` |
| `GET /api/dashboard/export?source=&date=` | 把 `dashboard.html` 和那天的日报嵌成一个单文件回给浏览器下载（`Content-Disposition`）。**嵌了数据的文件不设口令**，文件顶上写着这句 |

`source` 不认识 → `400`。`date` 格式不对 → `400`。错误一律 JSON：`{"ok":false,"code":…,"msg":…}`。

## 日报

```jsonc
{
  "ok": true,                 // 至少一块 ok 才 true
  "schema": 1,
  "date": "2026-09-17",       // 请求的日报日期
  "generated_at": "2026-09-18T09:30:12+08:00",
  "source": {"key": "workbench", "label": "工作台台账"},
  "asof": null,               // 「截至时刻」（Q5-C 留位）：接口给当天进行中的数时填 ISO 时间；日报为 null
  "progress": null,           // 「今日进度」（Q5-C 留位）：一个 block，或 null
  "reason": "",               // ok:false 时的人话
  "blocks": [ /* block */ ]   // 顺序 = 显示顺序；第一版三块：trade / order_monitor / churn
}
```

### block

```jsonc
{
  "key": "trade",             // 稳定的英文键；页面用它记折叠状态，不用它决定怎么画
  "label": "交易量",
  "date": "2026-09-17",       // 这一块**实际**的业务日期（Q17-A：三块可以不同一天）
  "ok": true,
  "reason": "",               // ok:false 时：为什么没有（「2026-09-17 没有台账」「出单监控没跑过」…）
  "kpis":     [ /* kpi */ ],
  "sections": [ /* section */ ],
  "series":   [ /* series */ ]
}
```

### kpi（指标卡）

```jsonc
{"key": "tpv", "label": "交易额", "value": 123456.78, "unit": "USD", "fmt": "money",
 "dod": 0.031, "prev": 119700.5, "note": "环比昨日"}
```
- `value` / `prev` / `dod` 算不出来是 `null`。`dod` 是比率（0.031 = +3.1%），**不是**百分数。
- `fmt`：`money` | `int` | `pct`（值是 0~1 的比率，显示成百分数） | `text` | `date` | `days`。

### section（表）

```jsonc
{"key": "top", "label": "Top 商户", "note": "同一商户的多个站点合起来算",
 "columns": [{"key": "商户名称", "label": "商户", "fmt": "text"},
             {"key": "tpv", "label": "交易额", "fmt": "money"},
             {"key": "dod", "label": "环比", "fmt": "pct"}],
 "rows": [{"商户名称": "…", "tpv": 1000.0, "dod": null}],
 "truncated": null}            // 或 {"shown": 10, "total": 57}
```
- `rows` 里的键就是 `columns[].key`；多出来的键页面忽略，少了显示成空。
- 列的 `key` 可以是中文（口径层的行本来就是报表列名），页面不在乎。

### series（趋势）

```jsonc
{"key": "tpv30", "label": "近 30 天交易额", "unit": "USD", "fmt": "money",
 "points": [{"x": "2026-08-19", "y": 1000.0}, {"x": "2026-08-20", "y": null}]}
```
- `y: null` 是**缺**，折线在那儿**断开**，不连过去（`§2.9`）。
- `x` 是日期或期次标签，按数组顺序画，不排序。

## 第一版三块吐什么（工作台台账做数据源时）

| block | 来自 | kpis | sections | series |
|---|---|---|---|---|
| `trade` | `churn.overview.build(days, date)` | 交易额 / 笔数 / 有交易站点数，各带 `dod`、`prev` | `top`（Top 商户，含环比、占比）、`by_mode`（按接入模式）、`by_owner`（按直签人） | 近 30 天的交易额、笔数（缺天 `null`） |
| `order_monitor` | `data/出单监控结果/出单监控结果_<date>.json` 的 `audit_counts` + `counts` | 报表总行数、通知+表 / 只写表 / 哪儿都没有 | `dispositions`（十三档各几行） | 近 14 天三个落点 |
| `churn` | `data/churn/state/<date>.json` | 今日命中数、有资格的、通道异常数 | `hits`（命中名单，前 N，截断自报）、`incidents`（通道异常） | 近 14 天命中数 |

## 口令与访问日志

- `config.json`：`"dashboard": {"viewers": [{"name": "张三", "passcode": "…", "enabled": true}], …}`
- 校验：`passcode` 全等且 `enabled`；名字只用来记日志，不进响应。
- 访问日志 `data/access.log`：一行一次 `2026-09-18T09:30:12+08:00\t张三\t/api/dashboard/daily\t2026-09-17`。
- 口令配置页 `/dashboard/admin`：**只允许本机回环地址访问**（`127.0.0.1` / `::1`），不设第二套口令；
  明文显示（Q13-A），存 `config.json`（在 `.gitignore` 里）。

## 公司接口的位置（Q4-C）

`config.json`：`"dashboard": {"company_api": {"base_url": "", "token": "", "timeout": 20}}`。
- `base_url` 空 → `sources` 里 `configured:false`，`daily?source=company` 回 `ok:false` + reason，**不是 500**。
- 填了 → `adapters/company_api.py` 去 `GET {base_url}/daily?date=…`（带 `Authorization: Bearer {token}`），
  期望对方回**这份契约的日报**；不合契约时回 `ok:false` + 校验错误列表（字段路径），不静默修。
- 将来公司只给原始明细：在同一个文件里加「接口字段 → 报表列名」的映射，再喂口径层（Q22-A）。
