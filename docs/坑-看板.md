# 看板仓库自己踩的坑

工作台那 28 条在 `docs/坑.md`（同步产物，§ 号沿用）。这份是**这个仓库自己**的，编号 §D1 起，和那边不撞。

---

**D1 · 默认端口不能是 5060：Chrome 直接拒绝，ERR_UNSAFE_PORT。**（2026-09-18）
5060 / 5061 是 SIP 端口，在 Chrome 的 unsafe port 名单里。curl 通、`python -m server` 日志正常、
页面却打不开 —— Chrome 连请求都不发，显示它自己的错误页，服务日志里**一行都没有**。
排查了两轮代理才发现是这个：先看浏览器错误页上的 `ERR_` 码，再查代理。
默认改成 5070；`config.example.json` 的注释写了。同名单里还有 6000、6665~6669、10080 之类，别挑。

**D2 · WSGI 应用不许自己发 `Connection: close`。**（2026-09-18）
工作台 §2.18.9 说 SSE 要 `Connection: close` —— 那是 Flask 那边的事。PEP 3333 禁止应用发 hop-by-hop 头，
wsgiref 会 `AssertionError` 直接 500，**每一条路由都 500**。而直接调 WSGI 应用的用例全绿，
因为没经过 wsgiref 的 handler。所以 `tests/server.py` 的 `call()` 用 `wsgiref.validate.validator` 包一层：
它断言的正是这一类（hop-by-hop 头、status 格式、header 类型、迭代器要 close）。
真起服务之后第一件事是 `curl /api/dashboard/health`，别只信用例。

**D3 · 起服务的脚本里别写 `pkill -f "python3 -m server"`。**（2026-09-18）
`pkill -f` 匹配的是整条命令行，跑这段脚本的 bash 自己的命令行里就有这串 —— 把自己杀了，
后面的命令一条不跑，exit 144，什么输出都没有。要写 `pkill -f "^python3 -m server"`（锚定开头）。

**D4 · 给 node 写脚本要在 Windows 上也能跑：import() 要 file:// URL，请求别走同步 stdin。**（2026-09-18）
`golden_js.mjs` 第一版 `import(path.join(ROOT, 'static/js/…'))`，Linux 上好好的，用户 Windows 机器上
`python tests/golden.py` 直接红 —— ESM 的 `import()` 在 Windows 上不认 `D:\…` 裸路径（`ERR_UNSUPPORTED_ESM_URL_SCHEME`），
而且 `fs.readFileSync(0)` 同步读 stdin 会抛 EOF / EAGAIN。仓库里 `jobs/conversion_run.mjs` 早就是
`pathToFileURL(...).href` + 异步 stdin 的写法，照它抄就行。这一版改成：模块全走 `pathToFileURL`，请求写临时文件传路径。
另外用例只截 stderr 最后一行（`Node.js v26.7.0`）等于没截，现在打最后 8 行。
⚠ 同步来的 `tests/*.mjs` 也是 `import(MODULES + 'x.js')` 的写法，在 Windows 上大概率同样跑不了 —— 那是工作台的文件，
要修回工作台修（`tests/_harness.mjs` 的 `MODULES` 改成 file URL），这里不动。
